# BoardReadyOps Assurance Hardening Program Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Execute the 2026-09-22 engineering audit as four reviewable hardening workstreams without losing traceability between trust claims, implementation, tests, and release evidence.

**Architecture:** The program is deliberately split by trust boundary. Cloud/evidence/provenance, tenancy/governance, supply-chain/release, and verification/architecture/docs each have an independent implementation plan. The program plan defines ordering, gates, and cross-workstream acceptance so no team closes an isolated task while leaving the end-to-end trust chain inconsistent.

**Tech Stack:** TypeScript, Node.js 24, pnpm, Vitest, PostgreSQL migrations, Next.js API routes, GitHub Actions, GitHub Rulesets, Biome, existing BoardReadyOps signing/provenance primitives.

**Spec:** `docs/superpowers/specs/2026-09-22-assurance-hardening-program-design.md`

## Global Constraints

- Baseline is `main@029d1be5ca82d0ebe212add9f9a0cbe22016c86f` / `v1.67.0`.
- Preserve all existing required CI/security checks unless a replacement is demonstrably stronger.
- Do not combine independent workstreams into one implementation PR.
- A credential never implies cloud-upload consent.
- Heuristic evidence remains non-blocking by default.
- Tenant authorization changes fail closed.
- Supply-chain references become more immutable, never less.
- User-facing trust claims are changed in the same PR that changes the behavior they describe.

## Review Focus

- Token present while cloud upload is unset must produce no network traffic.
- A metadata-only review must not leak snapshot-derived design information.
- A provenance manifest generated by the real export command must verify against the current source and commit.
- A tenant-scoped route must reject a valid credential from another tenant.
- A release/bootstrap path must remain reproducible when mutable tags/branches move.
